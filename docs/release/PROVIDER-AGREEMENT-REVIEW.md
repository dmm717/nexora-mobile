# Provider scope review — proposed Play declarations

Reviewed official sources 2026-10-04/05. This is evidence-backed release preparation, not legal advice or confirmation of account-specific contract acceptance. A custom-negotiated DPA is not required merely to use Google's service-provider exception; actual applicable scope and independent uses matter.

[Google Data Safety](https://support.google.com/googleplay/android-developer/answer/10787469) treats off-device and pseudonymous data as collection. Server-to-server transfer can count as sharing; processing on a developer's behalf/instructions can qualify for the service-provider exception. Ephemeral means memory-only for the necessary real-time request, not merely a short retention period.

## Speech: four different questions, not one “logging off” switch

- Source: native services/speech.ts uses short-audio REST conversation endpoint; language/format parameters, **no storeAudio=true**. This is not proof that all Azure settings are off.
- Owner previously observed no Azure Monitor diagnostic settings. That is owner-reported configuration evidence; this follow-up did not inspect the resource.
- Provider memory-only real-time audio documentation is endpoint-specific. Batch/custom model/training/storage settings differ; do not generalize.
- Play proposal is **Ephemeral=No conservatively** until actual release/resource meets the real-time memory-only definition. If owner verifies that scope, audio may qualify for Yes. Submitted transcripts/JD/answers stored by Nexora remain No.
